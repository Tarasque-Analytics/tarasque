================================================================================
  TARASQUE MODEL PIPELINE — Initial Implementation Summary
  Date: 2026-03-24
================================================================================

OVERVIEW
--------
This commit introduces model/pipeline/, a modular Python package that replaces
the monolithic scripts (volarbmodel_backtest.py, database_build_script.py) with
a structured framework for data acquisition, feature engineering, model
training, and backtesting.  The pipeline is designed to serve three sequential
goals:

  1. Query WRDS for a comprehensive historical dataset (CRSP, OptionMetrics,
     Compustat, FRED) and store it as partitioned Parquet.
  2. Provide a modular model pipeline for rapid iteration on features, models,
     and hyperparameters.
  3. Support large-scale backtesting across many tickers, date ranges, and
     model configurations without requiring architectural changes.

The canonical model architecture — the XGBoost / Random Forest / LassoCV
ensemble with inverse-RMSE weighting and GARCH(1,1) overlay — is ported
directly from volarbmodel_backtest.py.  New features are layered on top of this
proven foundation based on the economics and market analysis in
summary_march16.md.


PACKAGE STRUCTURE
-----------------
model/pipeline/
    __init__.py        Package docstring
    __main__.py        Enables `python -m model.pipeline`
    config.py          Central configuration (DataConfig, ModelConfig, BacktestConfig)
    data_loader.py     WRDS queries + Alpaca/yfinance continuation + Parquet storage
    features.py        Feature engineering (~30-35 features)
    models.py          GarchForecaster + EnsembleVolModel (XGB/RF/LassoCV)
    backtest.py        Walk-forward backtesting engine with 4 validation metrics
    run.py             CLI orchestrator (backtest / refresh_data / live modes)
    utils.py           Shared helpers (Black-Scholes, Monte Carlo, FOMC calendar)


================================================================================
  STEP 1: DATA ACQUISITION (data_loader.py)
================================================================================

PROBLEM
  The prior database_build_script.py queried only one WRDS table
  (optionm.vsurfd) for 30-day options at three delta levels.  The model was
  otherwise dependent entirely on Alpaca and yfinance for historical data,
  limiting both depth and breadth.

DESIGN
  data_loader.py introduces three cooperating classes:

  WRDSLoader — Sends monthly-chunked SQL queries to seven WRDS endpoints:

    Table                  Purpose
    ------------------     -----------------------------------------------
    crsp.dsf + msenames    Daily OHLCV, returns, shares out for 30 symbols
    crsp.dsi               S&P composite index returns
    optionm.vsurfd         IV surface: 4 DTEs x 5 deltas (20 grid points)
    optionm.secnmd         Ticker-to-SECID mapping for OptionMetrics
    comp.funda             GICS sector codes, dividend data
    comp.fundq             Quarterly earnings report dates (rdq)
    fred.data              9 macro series (treasuries, HY spread, inflation
                           breakevens, fed funds, dollar index)

    Monthly chunking (the proven pattern from database_build_script.py:28-77)
    prevents WRDS from killing long-running connections.  The OptionMetrics
    query uses a two-step approach: resolve ticker→SECID via secnmd first,
    then query vsurfd by SECID for maximum efficiency.

  ParquetStore — Reads and writes partitioned Parquet files organised by data
    type under a configurable base directory:

      {base_dir}/
          ohlcv/ticker=AAPL/data.parquet
          vsurfd/ticker=AAPL/data.parquet
          fred/data.parquet
          events/earnings/data.parquet
          events/dividends/data.parquet
          compustat_meta/data.parquet
          crsp_index/data.parquet

    The base_dir is configurable via the TARASQUE_BASE_DIR environment variable
    or the --base-dir CLI argument, allowing the same code to run on different
    machines without modification.

  AlpacaContinuation — After the WRDS historical window ends, this class
    appends recent data from Alpaca (OHLCV for stocks and ETFs) and yfinance
    (treasury rate proxies).  The public function append_recent_data() detects
    the last date in each stored dataset and fetches only the gap.

  The public API consists of two functions:
    - fetch_dataset(config) — queries WRDS for all data types, caches to
      Parquet, and returns a dict of DataFrames.  Skips re-query if cache
      exists unless force_refresh=True.
    - append_recent_data(config, existing_data) — extends the cached data
      with Alpaca/yfinance for the most recent trading days.

FEATURE PARITY (WRDS ↔ Alpaca continuation)
  Not all WRDS features can be replicated from Alpaca.  Specifically:
    - Historical IV surface data → only OptionMetrics provides this
    - Macro series (HY spread, breakeven inflation) → requires FRED API
    - GICS sector codes → Compustat (static, rarely changes)
    - Earnings/dividend dates → Compustat historically, yfinance for recent
  The pipeline is designed so that the WRDS data serves as the authoritative
  historical record and Alpaca/yfinance are used only for the trailing edge.

INITIAL SCOPE
  - 10 tickers: AAPL, MSFT, AMZN, META, GOOGL, MS, XOM, CVX, JNJ, CAT
  - 20 factor ETFs queried and stored (for future use)
  - 6 initial model ETFs: VIXY, HYG, USO, TLT, UUP, SPY
  - 5-year date range: 2021-01-01 to present


================================================================================
  STEP 2: MODEL PIPELINE (features.py, models.py, backtest.py)
================================================================================

FEATURES (features.py)
  The FeatureBuilder class consolidates and extends the feature engineering
  that was previously scattered across volarbmodel_backtest.py.

  Ported directly from the backtest (the proven baseline):
    - rv_TARGET          Garman-Klass 21d realised volatility, annualised
    - ret_TARGET         Log returns of the stock
    - tech_RSI           14-period RSI
    - tech_ATR           14-period ATR normalised by close price
    - ret_{ETF}          Log returns for the 6 core factor ETFs
    - event_fed_gravity  Inverse distance to next FOMC meeting
    - event_earn_gravity Inverse distance to next earnings date
    - vol_trend          RV / 63d rolling mean of RV (regime indicator)
    - vol_vel            5-day absolute change in RV (acceleration)
    - vol_of_vol         21d rolling standard deviation of RV

  New features added based on summary_march16.md analysis:

    Volatility:
    - rv_5d, rv_10d, rv_63d   Multi-scale GK realised vol windows
    - ewma_vol                EWMA(21) of squared returns (smoother estimator)

    Technicals:
    - tech_MACD_hist          MACD histogram (12/26/9) for momentum
    - price_regime            Close / 252d rolling high - 1 (drawdown depth)

    Options surface (from OptionMetrics — entirely new feature category):
    - iv_atm_30d              ATM implied vol (delta=50, 30 DTE)
    - put_call_skew_30d       OTM put IV minus OTM call IV at 30 DTE
                              Detects institutional hedging and directional
                              panic (summary_march16.md:86-93)
    - term_structure_slope    IV at 91 DTE minus IV at 30 DTE
                              Captures the market's forward vol expectations
    - vrp_wedge               Market IV minus model RV — the core volatility
                              risk premium signal
    - iv_atm_z_score          How stretched current IV is vs its own history

    Macro (from FRED):
    - macro_yield_curve_slope 10y-2y Treasury spread (recession indicator)
    - macro_hy_spread         ICE BofA HY index (credit stress)
    - macro_hy_spread_chg_5d  5-day momentum in HY spread
    - macro_breakeven_5y      5-year breakeven inflation rate
    - macro_dollar_ret        Log return of the broad dollar index

    Events:
    - event_div_gravity       Inverse distance to next dividend date

    Factor decomposition:
    - beta_spy                63d rolling beta to SPY
    - res_vol                 Annualised residual vol after SPY component
    - res_vol_vel             5-day change in residual vol

    Sector coupling (summary_march16.md:43,61):
    - corr_sector_21d         21d rolling corr with the stock's sector ETF
    - corr_sector_252d        252d rolling corr with sector ETF
    - sector_wedge            21d corr minus 252d corr — coupling/decoupling

  The sector ETF is determined automatically via GICS codes from Compustat
  (e.g., AAPL → Technology → XLK; MS → Financials → XLF).  Falls back to SPY
  if GICS data is unavailable.

  Total initial feature count: ~30-35.  With 5 years of daily data (~1260
  rows per ticker), the samples-per-feature ratio is ~36-42, comfortably
  above the 20-sample econometric minimum cited in summary_march16.md:62.

MULTICOLLINEARITY STRATEGY
  The full 20-ETF set has severe multicollinearity (SPY/QQQ, XLK/QQQ,
  IEI/IEF/TLT, etc.).  We address this in phases:

  Phase 1 (this commit): Use only the 6 core ETFs.  These are economically
    orthogonal: equity market (SPY), vol regime (VIXY), credit (HYG),
    energy (USO), rates (TLT), dollar (UUP).

  Phase 2 (future): Add 1-2 sector-specific ETFs per stock using GICS codes.
    E.g., AAPL/MSFT get XLK; MS gets XLF; XOM/CVX get XLE.  This adds
    explanatory power without introducing broad multicollinearity because
    each stock only sees its own sector ETF.

  Phase 3 (future): Orthogonalization — regress correlated ETFs against one
    another to extract unique signals (summary_march16.md:39).  Also
    consider PCA on the full ETF set for dimensionality reduction.

  The database always stores all 20 ETFs so data is ready when we expand.

MODELS (models.py)
  Ported directly from VolArbModel in volarbmodel_backtest.py:352-466.

  GarchForecaster:
    GARCH(1,1) with Skewed-T distribution.  Returns are scaled to percentage
    for optimizer stability.  Falls back to naive std*sqrt(252) on fit failure.

  EnsembleVolModel:
    Three models trained at each of three horizons (21d, 63d, 126d):
      - XGBoost (n_est=100, depth=4, lr=0.05, regularised)
      - Random Forest (n_est=100, min_leaf=5 — to be bumped to 50 with full DB)
      - LassoCV (TimeSeriesSplit CV, inherent feature selection)

    Walk-Forward Analysis (WFA):
      1. Fit a final StandardScaler on all available data
      2. For each TimeSeriesSplit fold:
         a. Fit a separate fold scaler on training data only (strict OOS)
         b. Train all three models in log-volatility space
         c. Exponentiate predictions to linear space for economic RMSE
      3. Compute inverse-RMSE weights with a minimum floor of 0.10
         (new — prevents any single model from dominating the blend)
      4. Final fit of all models on the fully scaled dataset

    New additions beyond the backtest:
      - model_names parameter: train only a subset of models (e.g., ["XGB"])
        for ablation studies during hyperparameter iteration
      - Minimum ensemble weight floor: configurable in ModelConfig
      - SHAP explainability via TreeExplainer (ported from backtest :469-514)

BACKTEST (backtest.py)
  BacktestEngine implements walk-forward evaluation:

  run_single_ticker():
    For each step window (default 25 trading days):
      1. Select training data (expanding or rolling window)
      2. Train a fresh EnsembleVolModel from scratch
      3. Generate out-of-sample predictions for the next step_days rows
      4. Advance the window and repeat

    Minimum training set: max(252 days, 20 * n_features) per the
    econometric rule of thumb (summary_march16.md:62).

  run_sector_sweep():
    Iterates over all configured tickers, builds features, runs the
    single-ticker backtest, and aggregates results into a CSV.

  Four validation metrics (all from summary_march16.md):

    1. RMSE — standard forecast error in linear vol space
    2. Mincer-Zarnowitz regression — regress actual on predicted.
       Ideal: alpha≈0, beta≈1, R² high.  The classic first-round validity
       test for vol forecasts (summary_march16.md:24,76).
    3. QLIKE — quasi-likelihood loss function that penalises underestimation
       and overestimation asymmetrically (summary_march16.md:26).
       Formula: mean(actual/pred - log(actual/pred) - 1)
    4. Event capture rate — what fraction of ≥2σ realised vol spikes did
       the model predict elevated vol for?  This is the risk-management
       metric: does the model spike before the stock does?
       (summary_march16.md:27,77)

CLI (run.py)
  Three modes accessible via command line:

    python -m model.pipeline --mode refresh_data --base-dir /path/to/data
      Query WRDS and/or append Alpaca data.  Print data summary.

    python -m model.pipeline --mode backtest --tickers AAPL MSFT
      Full walk-forward evaluation.  Saves results CSV.

    python -m model.pipeline --mode live --tickers AAPL
      Single-day inference: train on all available data, print forecast
      curve, GARCH overlay, fair ATM vol, top feature drivers.

  Additional flags:
    --base-dir     Override Parquet storage root (env: TARASQUE_BASE_DIR)
    --tickers      Override the default 10-ticker universe
    --models       Subset of [XGB, RF, LassoCV] for ablation
    --force-refresh  Re-download even if Parquet cache exists


================================================================================
  STEP 3: LARGE-SCALE ITERATION (design-for, not yet implemented)
================================================================================

The modular architecture is designed so that Step 3 requires no structural
changes — only new wrapper scripts that vary configurations:

  Hyperparameter search:
    ModelConfig is a dataclass.  A grid search script generates config
    variants and calls BacktestEngine.run_single_ticker() for each.  Results
    are logged to CSV with a config hash for comparison.

  Feature ablation:
    FeatureBuilder.build() returns all features.  The caller subsets the
    predictor list to test feature groups (options-only, macro-only,
    technicals-only, etc.).  The --models flag already supports model-level
    ablation.

  Quintile spread analysis:
    After running predictions across all tickers on a given date, rank by
    predicted risk, bucket into quintiles, and measure forward returns per
    bucket.  This tests the Informational Coefficient (IC) — whether the
    model can correctly rank the market from safest to most dangerous
    (summary_march16.md:78-81).

  Dynamic feature weighting:
    XGBoost and Random Forest both accept sample_weight arrays.  An
    exponential decay weighting scheme (recent data weighted higher, as
    discussed in summary_march16.md:65) can be applied without changing
    model code.


================================================================================
  KNOWN ISSUES AND NOTES
================================================================================

  1. Bug in volarbmodel_backtest.py:146-148 — missing comma between "USO" and
     "TLT" causes Python string concatenation ("USOTLT").  The pipeline's
     config.py corrects this with explicit comma-separated entries.

  2. CRSP uses a negative price convention (negative values indicate bid/ask
     average rather than closing price).  features.py handles this by taking
     absolute values during the OHLCV pivot.

  3. OptionMetrics SECID mapping is required before querying vsurfd.  The
     data_loader handles this as a two-step process (secnmd lookup first).

  4. The Alpaca continuation for IV surface data is approximate — it uses
     option chain snapshots with Black-Scholes inversion rather than the
     standardised OptionMetrics volatility surface.  This is acceptable for
     the trailing edge but should not be used for backtesting.

  5. Random Forest min_samples_leaf is set to 5 for the initial small
     dataset.  The backtest file's own comment (line 365) notes this should
     be bumped to 50 when the full database is in place.

  6. FRED series availability varies — some series (e.g., DTWEXBGS) may have
     different start dates.  The loader forward-fills across weekends and
     holidays to align with trading day frequency.

  7. All features are strictly point-in-time.  The only forward-looking
     columns are the targets (y_21, y_63, y_126) which use .shift(-h).
     No revised economic figures are used; only first-release data.
